# agent-doc-kit

从无限路径收到可走的路。一次处理一个仓库的工作面（可再点其中一块或一部件）。环境会变，所以可再跑。

五条与工作面 → [`philosophy/00.md`](philosophy/00.md)。写作工艺 → skill `writing-for-agents`（改 `SKILL.md` 或协议文档时加载）。

用 agent 的入口是按用途铺点名仓库。人格落点是 skill。不调度别的 skill。禁止使用全局 `AGENTS.md`。

## 何时用

用户要给仓库铺工作面、要用 agent 先配、路已经偏了、或只要对照表。

模式：`bootstrap` / `reshape` / `audit`。

## 流程

### 1. 锁定

目标仓库根、模式。用户可再点四块或一部件；未点则 `bootstrap` 铺最小集、`reshape` 修裂缝。未点名仓库先问。

完成：用户认可路径、模式、块/部件（或整仓最小集）。

### 2. 加载 00

读 [`philosophy/00.md`](philosophy/00.md)。

完成：写出这轮工作面四块、部件与写盘权限。

### 3. 探面

只读。用该仓事实，不用 00 的表冒充现实。看：身份句、已有项目 `AGENTS.md`、完成入口能否跑、工具与环境、人格沉积、树里已有的 residue、会误进窗口的沉积。

完成：十行内写出已有材料、它现在是哪一块/部件、与五条的裂缝。

### 4. 对照表

逐条对照五条。检查复述环境、index 在讲行为、人格进了 `AGENTS.md`、编造不存在的预言机、只写 markdown 而环断、步骤散文进始终加载文件、把代码仓骨架套到非代码仓、空文件充活约束。

`audit` 到对照表为止。

完成：对照表已交用户；audit 在此停。

### 5. 设计落点

仅 `bootstrap` / `reshape`。按本仓事实画文件表。默认最小集。代码仓缺结构时打开 [`shapes/`](shapes/) 当骨架，按本仓事实填进已有文件；禁止整文件覆盖。树里没有的指针删掉。

`bootstrap` 最小集：

1. 一句身份（这份仓库为什么存在）
2. index：命令名、一句话布局、必读指针 + 触发（树里已有的才指）
3. 预言机：已有则指；用途需要而无则列入要配的入口，造完再指
4. 工具与环境：用途需要则列入安装与入口
5. 人怎么跟这个仓里的 agent 说话：需要则写成项目 `AGENTS.md` 的一行

完成：用户同意文件表；或用户要求停。

### 6. 确认后写入

展示摘要 → 用户确认 → 写入。改协议文档时遵守 `writing-for-agents`。

完成：磁盘与确认稿一致。

### 7. 自检

对照 00「完成」。另查：未写入口菜单；写出的完成命令能跑，或缺口已列出。

完成：自检全过或残留已列出。

## 改 kit

改 [`philosophy/00.md`](philosophy/00.md) 或 [`shapes/`](shapes/)。

完成：磁盘与确认稿一致。其他仓另一次点名。
