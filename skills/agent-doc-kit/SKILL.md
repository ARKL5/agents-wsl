# agent-doc-kit

从无限路径收到可走的路。一次处理一个仓库的环境（可再点其中一部件）。环境会变，所以可再跑。

五条与部件 → [`philosophy/00.md`](philosophy/00.md)。写作工艺 → skill `writing-for-agents`（改 `SKILL.md` 或协议文档时加载）。

不配 harness。不写人格。不调度别的 skill。

## 何时用

用户要给仓库铺环境、路已经偏了、或只要对照表。

模式：`bootstrap` / `reshape` / `audit`。

## 流程

### 1. 锁定

目标仓库根、模式。用户可再点其中一部件；未点则 `bootstrap` 铺最小集、`reshape` 修裂缝。未点名仓库先问。

完成：用户认可路径、模式、部件（或整仓最小集）。

### 2. 加载 00

读 [`philosophy/00.md`](philosophy/00.md)。

完成：写出这轮环境部件与写盘权限。

### 3. 探面

只读。用该仓事实，不用 00 的表冒充现实。看：身份句、已有项目 `AGENTS.md`、预言机（测试 / lint / check 是否已在环境里）、人格沉积、树里已有的标准 / 领域词 / ADR。

完成：十行内写出已有材料、它现在是 index / residue / 预言机 / 主文档、与五条的裂缝。

### 4. 对照表

逐条对照五条。检查复述环境、index 在讲行为、人格进了 `AGENTS.md`、编造不存在的预言机、学习仓硬套产品仓标准、空文件充活约束。

`audit` 到对照表为止。

完成：对照表已交用户；audit 在此停。

### 5. 设计落点

仅 `bootstrap` / `reshape`。按本仓事实画文件表。缺结构时打开 [`shapes/`](shapes/) 当骨架，按本仓事实填进已有文件；禁止整文件覆盖。树里没有的指针删掉。非产品仓更薄。

`bootstrap` 最小集：

1. 一句身份（这份仓库为什么存在）
2. index：必读指针 + 触发（树里已有的才指）
3. 预言机指针：环境里已经存在的那条完成命令。没有就不编
4. 人怎么跟这个仓里的 agent 说话：需要则写成项目 `AGENTS.md` 的一行

完成：用户同意文件表；或用户要求停。

### 6. 确认后写入

展示摘要 → 用户确认 → 写入。改协议文档时遵守 `writing-for-agents`。

完成：磁盘与确认稿一致。

### 7. 自检

对照 00「完成」。另查：未写入口菜单。

完成：自检全过或残留已列出。

## 改 kit

改 [`philosophy/00.md`](philosophy/00.md) 或 [`shapes/`](shapes/)。

完成：磁盘与确认稿一致。其他仓另一次点名。
