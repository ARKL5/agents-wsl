# 工程与交付思想

根路由注入「编码标准、权威面、门禁」指针，指向工程默认。默认窗口里这份文件保持薄：本仓数字 + 小改默认。规划阶段、claims 正文、过程配额不写进来。

## 小改默认

- 当轮用户已经要求的范围内，小而可逆的改动直接做。含糊不影响授权时写假设并继续。  
- 实现授权来自当轮用户。审查、解释、报告不构成实现授权。  
- 改动幅度跟当轮任务走。用户要重写、破兼容、改契约：按该幅度改到行为权威面。小补丁只服务小修。  
- 默认做完再报告。打断用户只为：当轮没要求却会扩/缩产品边界、不可逆破坏、或本仓已写明须确认的供应方。  
- 路径、测试结果、commit：只报查过或跑过的。  
- **主线程 leader**：架构、文档权威、最终验证不随委派转移。

## 调查

局部任务从公共入口、类型与测试开始。跨模块先列风险面再取证。先可验证纵向路径，再抽模块。**根因修：** 共享分支一处修。取证深度由任务边界决定，仓内不写过程配额。

## 门禁：两层

| 层 | 含义 |
| --- | --- |
| **seam 验证** | 改动面；可子集 |
| **delivery gate** | 声称完成时的整组检查 |

Python 仓常见（以本仓配置为准）：

```bash
uv run ruff format --check .
uv run ruff check .
uv run pyright
uv run pytest
```

完整门禁通过仅主线程声称。真实供应方默认须用户确认。单次 smoke ≠ 质量证明。
