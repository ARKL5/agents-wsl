# 工程偏好

约束本仓实现与验证默认。  
**行为权威面（本仓须填）：** 代码、测试；按仓补迁移、类型、CLI、schema、HTTP 契约。  
领域词 → 根 `CONTEXT.md`。难逆取舍 → `docs/adr/`（若使用）。

## 小改与权威

- 当轮用户已经要求的范围内，小而可逆的改动直接做。含糊不影响授权时：写下假设并继续。实现授权来自当轮用户（请求、已接受路线、或当前任务已立好的工作流）。审查、解释、报告不构成实现授权。  
- 改动幅度跟当轮任务走。用户要重写、破兼容、改契约：按该幅度一次改到行为权威面。小补丁只服务本来就是小修的任务。  
- 默认做完再报告。打断用户只为三件事：当轮没要求却会扩/缩产品边界、不可逆破坏、或本文件已写明须确认的供应方。  
- 当轮用户要求改形状时，用行为权威面承接；正式文档随后对齐。  
- **能力认实现面：** 现行行为只认行为权威面。map/spec 是目标与约束。与正式文档冲突时，先从运行入口、迁移和测试确认行为。  
- 路径、测试结果、commit：只报查过或跑过的。保留他人无关未提交修改。  
- **主线程是 leader：** 架构、文档权威、最终验证与 delivery gate 不随委派转移。

## 本仓结构与栈（须填）

- 栈、目录约定、领域权威留本地的名单（若有）。

## 交付与本地门禁

完成 = 可观察行为闭合。

| 层 | 含义 | 谁可声称 |
| --- | --- | --- |
| **seam 验证** | 针对改动面；可子集 | Worker 可报 |
| **delivery gate** | 声称完成时的整组检查 | 仅主线程跑完后声称 |

本仓须填 delivery gate 命令。Python 常见：

```bash
uv run ruff format --check .
uv run ruff check .
uv run pyright
uv run pytest
```

范围以本仓配置为准。普通测试用 fake / 进程内 double。真实供应方：门禁通过后；无 standing authorization 时每次须用户确认。只报告实际执行过的验证。
