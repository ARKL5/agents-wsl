# Learn Interview

同一段对话里进入**学习分支**：先用全知视角把地图铺开，再访谈，直到收成**你的理解**。不是开课，不是为了拍板，也不是审计划（那是 `grill-me`）。

用户说「随便聊」才放开锚；没说则以当前一个主题为锚，顺着问可以，结束仍收回这个主题。

## 1. 进分支

从用户这句话或当前对话定主题。含糊到无法开讲时，只问一次「这一场谈什么」。

写一句可见围栏：现在进入学习分支、主题是什么。此分支只形成理解：不改产品代码，不落盘。

**完成：** 主题已钉住（或用户已声明随便聊）；围栏已写出。

## 2. 铺地图

先讲，不卖关子。用户知识有限，缺的是图，不是考题。

一张地图里写清：这块地有什么、为什么会出现、没有它会怎样、常见分叉与各自代价。本仓能查的对着代码、测试、ADR 核；核过的标成本仓标本。其余标成一般计算机图景，不冒充本仓事实。

一次给一张能站住的图，不为了显得深刻而切八刀。

**完成：** 用户已经看见完整图，不必先猜。

## 3. 访谈

对着地图谈，让用户用自己的话接住、改写、指出还虚的地方。跟着他的问题走；有锚时每段仍能指回主题。

用户打字慢就用选择题。事实自己查，不问他仓库里已有的东西。

还虚就补一块地图再谈，不要改成讲义倾销。

**完成：** 用户已经用自己的话讲过，或改过你代写的草稿；不是只听过一遍。

## 4. 你的理解

整理成他认的几句，给他改。默认结构：

```text
主题：
我现在的理解：
还虚的地方：
```

他改完或点头，这一场的理解才成立。决策若碰巧出现，写进「我现在的理解」，不另做 return card。

**完成：** 用户确认了这份理解，或声明「这轮先挂着」。

## 5. 出分支

宣布学习分支结束，停。

只有用户明确说「写成卡 / 记下来」才进入第 6 步。只有他说「按这个做」才回到实现。

**完成：** 理解已出示；未受指示时没有写文件、没有改产品代码。

## 6. 落盘（仅当用户点名）

先出示将要写入的正文，等他认可。

当前仓若有思想卡模板（例如 `learn/cards/_template.md`），按该模板填**他确认过的理解**，并更新学习区自己的登记表。没有模板就问一句写到哪，按他给的路径写一份短笔记。

**完成：** 文件内容与「你的理解」一致；登记表（若有）已更新。
