# 权限与功能取舍

调整权限、功能启停或精简模型上下文时使用本文件。界面和扩展设计遵循对应 harness 的个人约定。

## 权限

默认开放权限，避免逐次批准。读写、命令执行、委派和联网等核心能力保持可用。

## 上下文成本

目标是减少永远不用、却持续进入模型上下文的内容。会使用或未来可能使用的能力保留，即使其描述持续加载。

关闭功能前，先确认它对模型上下文的影响：

| 上下文影响 | 判断依据 | 默认处理 |
| --- | --- | --- |
| 按需加载 | 只常驻简短入口，调用时才加载正文，例如 skill | 保留 |
| 持续注入 | 每次请求都附带工具描述或系统说明，即使未调用 | 按下面的关闭条件判断 |
| 不减少上下文 | 仅改变界面，或只拒绝调用而仍保留工具描述 | 不为节省上下文而关闭 |

无法确认上下文成本或关闭效果时，保留并说明尚未核实。

## 关闭条件

自动精简只处理同时满足以下条件的功能：厂商内置、持续注入、确定永远不用，并且有官方配置机制能将相关描述从上下文移除。用户安装的 skill、工具或扩展只按本次明确要求调整。

核查当前官方契约，并在关闭后验证相关工具或说明已移除。权限拒绝只有在确实移除上下文内容时才算精简；仅阻止执行不算。

已有的关闭决定见各 harness 参考文件。参考文件未记录为关闭的既有能力保持原样；不得因为一次局部任务或核查结果自行新增关闭。自动精简只落实用户本次明确要求，或核对已记录的关闭决定是否仍然有效。各参考文件已记录的关闭决定优先于上表的默认处理；上表只用于判断尚未记录的能力。用户要求先选择关闭项时，按加载方式列出候选及关闭效果，等用户选择后修改。
